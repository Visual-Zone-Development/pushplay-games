@AGENTS.md

Pick the skill by intent: making a game → `new-game`; changing, tuning or improving an existing game → `improve-game`; something broken (crash, failing check, controls, performance) → `debug-game`. Specialists, used on their own or from those three: how it feels to play (responsiveness, juice, impact) → `game-feel`; levels, waves, procedural content and the difficulty curve → `level-design`; sound effects and music → `game-audio`; HUD, menus, onboarding and results screens → `game-ui`; measuring balance and pacing with headless bots → `playtest`; bosses and finales → `boss-design`; unlocks, upgrades, achievements and daily challenges → `progression`; colourblind modes, remapping and assists → `accessibility-audit`; story, characters and dialogue → `story-and-dialogue`; frame rate, stutter and load time → `performance-pass`; player-facing "what's new" notes for an update → `release-notes`; enemy and CPU behaviour → `enemy-ai`; following and framing → `camera`; collisions, bounce and vehicles → `physics-feel`; couch co-op and versus → `local-multiplayer`; online lag and sync → `online-netcode`; a party game's phone screen → `party-phone-screen`; phone motion controls (tilt, steering wheel, swings, throws) → `motion-controls`; the library cover and banner → `cover-art`; the library screenshot and shareable shots or clips → `screenshots`; other languages → `localization`. Not sure which direction to take → `prototype-sprint`; bringing in an existing web game → `port-game`; updating the build kit or syncing from the template (only when asked) → `kit-upgrade`. For a game's art: a new asset or a rebuild from a reference → `model-asset`; one focused change to one character, prop, sprite or building → `edit-asset`; how things move → `animate-asset` (all three keep the game's `STYLE.md` consistent; add `canvas2d-assets` for 2D games or `threejs-models` for 3D models built in three.js code). The look of the whole screen (materials, palette, textured backgrounds, UI that looks like part of the world, fonts, atmosphere; "make it look like this screenshot", "it looks flat") → `art-direction`; a hand-made 3D character from a file (VRoid, Blender, GLB/VRM), anime / cel-shaded look or a character creator → `character-models`; pixel art of any kind (8-directional characters and their animations, tilesets and maps, props, pixel UI; "make it look like PixelLab") → `pixel-art`; conversations, NPC dialogue, branching choices, character voices and the dialogue box → `dialogue` (the story bible and between-level beats stay with `story-and-dialogue`); the world itself, for any genre and camera (backgrounds, parallax, tiles and autotiling, maps and rooms, scattering, skies, time of day, weather, readability of walkable vs blocked) → `environments`. Painted sprites, textures or key art from the user's own image API key (only if one is set) → `npm run art`, see `docs/game-design/generated-art.md`. You can read PNG files, so after `npm run check` open the cover, hero and screenshot images it prints and improve the art or game until they look right.
