# 3D games (three.js)

Use 3D when the idea needs it: depth, a camera moving through space, a racing track. 2D canvas is faster to build and easier to make readable on a 7" screen, so it's the default.

## Setup

```sh
npm run new-game <id> --vite
npm install three
```

Commit the updated `package-lock.json`. Import from `three` and from `three/examples/jsm/...` for loaders and controls. Everything is bundled by Vite, so there are no CDN links.

## Handheld budget

The Steam Deck's and Legion Go's GPUs are roughly low-end laptop GPUs, and the Legion Go drives a 2560×1600 panel. Stay well under these numbers for a steady 60fps:

| Thing | Budget |
|---|---|
| Draw calls | < ~150 per frame (check `renderer.info.render.calls`) |
| Triangles | < ~100k on screen |
| Shadow-casting lights | 1 (a directional light), shadow map ≤ 1024, or baked/blob shadows; or none |
| Textures | ≤ 1024×1024, few of them; prefer vertex colors |
| Post-processing | none, or one cheap pass (no SSAO/SSR, no bloom by default; if you add bloom or shadows, make them a Settings toggle in `extra` that defaults off) |
| Pixel ratio | `renderer.setPixelRatio(Math.min(devicePixelRatio, 1))` on a fixed 1280×800 render surface |
| Particles | `THREE.Points` or one `InstancedMesh`, capped |

**Tricks that help:**
- `InstancedMesh` for anything repeated (trees, coins, asteroids).
- Merge static geometry (`BufferGeometryUtils.mergeGeometries`).
- Reuse materials.
- Fog to shorten the far plane.
- Don't allocate `new Vector3()` inside the frame loop; reuse scratch vectors.

## Render size and scaling

Render to a fixed **1280×800** surface at pixel ratio ≤ 1 and let `fit.js` scale and letterbox it, the same as the 2D starter. The 3D canvas is never rendered at DPR 2: a Legion Go at 2560×1600 would be four times the pixels for no readable gain.

```js
import { fitCanvas } from './fit.js'
renderer.setPixelRatio(Math.min(devicePixelRatio, 1))
renderer.setSize(1280, 800, false) // false = don't touch the CSS size; fitCanvas owns it
fitCanvas(renderer.domElement, { w: 1280, h: 800, maxDpr: 1, letterbox: '#000' })
```

Keep `camera.aspect = 1280 / 800` and don't add your own `resize` handler. Draw the HUD on a separate 2D canvas sized with its own `fitCanvas(hud, { w: 1280, h: 800, maxDpr: 2 })` so text stays crisp (see *HUD*). Use the game's background colour for `letterbox` so bars disappear on 16:9 windows.

## Look

These settings make most of the difference between "programmer art" and a finished look (Simon Willison's Emberwick and Battle Drones use them), and they cost almost nothing:

```js
renderer.toneMapping = THREE.ACESFilmicToneMapping // or NeutralToneMapping
renderer.outputColorSpace = THREE.SRGBColorSpace
scene.add(new THREE.HemisphereLight(0xbcd4ee, 0x5b4a32, 1.1)) // cool sky over warm ground, never plain grey
const sun = new THREE.DirectionalLight(0xfff2dc, 2.4) // strong, slightly warm, from the upper left
scene.fog = new THREE.Fog(HORIZON, near, far) // same colour as the sky dome's horizon
```

- **Sky:** a `BackSide` sphere with a top/horizon/ground gradient shader instead of a flat clear colour.
- **Vertex colours with jitter:** nudge each face's colour a few percent, darken near the ground (fake AO) and lighten top edges, so shapes separate even with shadows off. Give the main objects an accent-colour patch on top (the camera looks down) and `emissive` lights.
- **Low-poly:** `MeshLambertMaterial({ flatShading: true, vertexColors: true })`, a `HemisphereLight` (sky/ground colors) plus one `DirectionalLight`.
- **Toon:** `MeshToonMaterial` with a 3-step `gradientMap` (`NearestFilter`). For outlines, use an inverted hull: clone the mesh, use a black `BackSide` material and scale by 1.03.
- Saturated colors read better than realism at handheld size. Make the player the brightest object.
- See [art-directions.md](art-directions.md) for palettes.

## Action that reads in 3D

How a top-down 3D action game goes from grey boxes on a grey plane to a lit arena that's satisfying to watch, roughly in order of impact. The example is a dusk stone courtyard for an arena shooter; swap the materials and palette for the game's own look (STYLE.md).

**The stage**
- **A floor made of something.** Bake a stone-tile `CanvasTexture` once at startup (512–1024 px): tiles with a few percent of value and hue jitter each, darker mortar lines, worn edges, a little noise (`texture.js` from the art-direction toolkit has the building blocks). `RepeatWrapping`, `anisotropy = 4`, `colorSpace = SRGBColorSpace`. A plain coloured plane is the single biggest "prototype" signal.
- **Walls and blocks that belong.** Low walls around the arena, cover blocks in a lighter stone with a darker base (fake AO from vertex colours) and a top-edge highlight. A few props on the edges (crates, braziers, banners) say where you are.
- **Dusk lighting.** A cool hemisphere light (indigo sky over a dark warm ground), a low warm directional key from one side casting the only shadows (`PCFSoftShadowMap`, map ≤ 1024, the shadow camera fitted tightly around the player and moved with them), and warm light pools at torches or braziers. Prefer emissive meshes plus additive glow decals for the pools; real `PointLight`s cost every material a light, so 2–4 at most. Fog in the sky's colour hides the edges.
- **Value plan.** Floor and walls sit in the mid-darks; the player, enemies, shots and pickups are the only bright, saturated things. The player gets one hero colour (cyan on a navy floor, say) that nothing else uses.

**The actors**
- **A ring under the player** in the hero colour (a flat `RingGeometry` just above the floor, additive, gently pulsing) plus an aim arc or reticle toward `input.aimX / aimY`. It finds the player instantly in a crowd and shows where the shots go.
- **Enemies telegraph.** A ring on the ground that fills or flashes before an attack or a charge, in the danger colour, timed from the existing attack (a visual on the rule, not a new rule).
- **Hit flash.** Set the hit mesh's `emissive` to white or the hit colour for 50–80 ms, then ease back. Give each enemy its own material clone, or use per-instance colour on an `InstancedMesh`.

**The impact**
- **Ember and spark bursts.** One pooled `THREE.Points` (or one `InstancedMesh` of small quads) with `AdditiveBlending`, `depthWrite: false`, size attenuation, warm colours (amber to red), gravity and drag. 10–20 per hit, 30–60 per kill, ≤ 300 alive in total.
- **Scorch decals.** A flat quad with a radial-gradient canvas texture where something died or exploded, `polygonOffset` to avoid z-fighting, a capped ring buffer (≈ 40) that fades out. The arena remembers the fight.
- **Score pops.** "+10", "+30" rise and fade from where the enemy died. Project the world position each frame (`v.copy(pos).project(camera)`, then `x = (v.x + 1) / 2 * 1280`, `y = (1 - v.y) / 2 * 800`) and draw the text on the **HUD canvas** with an `easeOutBack` pop: crisp at DPR 2, no 3D text needed.
- **Fake bloom.** A soft additive sprite (a baked radial gradient) behind shots, muzzle flashes, the player ring and torches. It reads as glow at almost no cost; a real bloom pass stays off, or a Settings toggle that defaults off.
- **Camera kick.** Shake is a small offset of the camera's position (0.05–0.3 world units, trauma² × noise) plus a tiny roll, never moving the world; a short FOV punch on the biggest hits. All of it off with `reducedShake`.

**The HUD**
- One plate in a corner: a dark translucent panel with a thin light edge; small letter-spaced caps for labels (SCORE, WAVE), big tabular numbers, a segmented health bar in the hero colour. Ease numbers when they change and pop them on big gains. Keep it ≥ 32 px from the edges and away from where the action happens.

Check every step with the before / after capture of the `polish-pass` skill: the same seed and autopilot at the same frames shows what each step really bought.

## Camera defaults

| Genre | Camera |
|---|---|
| Racing / runner | Chase cam behind and above, smoothed with `lerp` (~0.1 per frame at 60fps; scale by `dt`), slight FOV kick on boost |
| Platformer (3D) | Third-person, auto-follow; right stick orbits; recenters behind the player |
| Top-down action | Fixed-angle isometric-ish (~50° pitch), follows the player |
| Puzzle / board | Fixed or LB/RB rotate in 90° steps |

The right stick is `input.aimX` / `input.aimY`; keyboard players get the same with the arrows or `input.pointer` (a mouse-look that also works from the stick). Never require the mouse, and never grab the pointer lock without a stick alternative. Pause, settings and all menus follow the same rules as 2D games: `menu.js`, `settings.js`, `input.onPause`, and no quit of your own.

## HUD

Draw the HUD and every menu on a **2D canvas overlaid on the WebGL canvas**, positioned in the same 1280×800 space and sized with its own `fitCanvas` (DPR up to 2). This is simpler than 3D text and stays crisp. Follow the usual rules: text ≥ 24px, keep it away from the outer 32px, prompts from `input.label` / `drawPrompts`. Call `input.attach` on the top-most canvas so clicks and taps reach the menus.

## Models

```js
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js'
const gltf = await new GLTFLoader().loadAsync('assets/models/ship.glb')
scene.add(gltf.scene)
```

Put models in `public/assets/models/` so Vite serves them as-is. See [assets.md](assets.md) for size limits and licenses. Draw a loading screen while models load: the check takes its screenshot at 3 seconds and presses Start soon after, so the title and pause screens must not wait on models. Add audio through `audio.js` like any other game; 3D is not a reason to ship silent.

## Models built in code

Characters, creatures, vehicles and props can also be built in code instead of loaded: sculpted parts on a small
skeleton with blended procedural animation, drawn with instancing so hundreds of copies cost a few dozen draw calls.
The **threejs-models** skill has the toolkit (`sculpt.js`, `rig.js`, an asset viewer). The engine-agnostic workflow
is in **model-asset** (build to a reference the user provides, comparing renders every round), **edit-asset** (one
focused change) and **animate-asset** (natural motion that fits the game's physics). A game that uses them keeps a
`STYLE.md` (palette, proportions, shared materials, animation timing, asset catalogue) so every asset matches.

## Art

`art/cover.html` can render the actual three.js scene (import the built bundle or a small dedicated script), or you can draw the key model as flat SVG polygons in the same palette.
